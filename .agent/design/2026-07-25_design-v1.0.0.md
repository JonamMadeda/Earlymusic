## 1. Color System

### Brand / Accent
| Token | Value | Usage |
|-------|-------|-------|
| `--color-accent` | `#FF2400` (Scarlet Red) | Primary accent for active states, buttons, links, indicators, waveform equalizer, "New" badges, highlight borders |

### Neutral Palette (Tailwind v4 defaults)
Used extensively across the app for text, backgrounds, borders, and surfaces:

- `neutral-50`  — subtle section backgrounds, skeleton loading
- `neutral-100` — borders, divider lines, secondary backgrounds
- `neutral-200` — light borders, input borders
- `neutral-300` — placeholder text, muted dividers
- `neutral-400` — secondary text, metadata, icons (inactive)
- `neutral-450` — custom shade between 400–500 for empty-state descriptions
- `neutral-500` — body text (inactive nav items)
- `neutral-600` — body text (sidebar recent songs)
- `neutral-700` — menu item text
- `neutral-800` — "New" badge text
- `neutral-900` — primary text, headings, active nav

### Background
- **Canvas:** `#ffffff` (white)
- **Surfaces:** `white`, `neutral-50/60`, `neutral-50`
- **Glass effects:** `bg-white/70`, `bg-white/80`, `bg-white/95` with `backdrop-blur-xl`, `backdrop-blur-2xl`
- **Skeleton:** subtle neutral tones

### Semantic
- **Accent overlay:** `accent/5`, `accent/8`, `accent/10`, `accent/20` (opacity variants)
- **Error/Alert:** `amber-50` bg, `amber-200` border, `amber-900` text
- **Online/Offline:** `neutral-50`/`neutral-500` for offline indicator

### Song Avatar Gradient
Each avatar generates a unique pastel gradient based on song title hash:
- Hue: 0–360 (avoiding green range 55–175)
- Saturation: 55–75%
- Lightness: 55–70%
- Two-stop linear gradient (135deg) with +30deg hue shift

## 2. Typography

- **Font Family:** `Inter` (Google Font, latin subset)
- **Scale:** Uses Tailwind size classes (`text-xs` through `text-2xl`)
- **Weights:** `font-medium` (500), `font-semibold` (600), `font-bold` (700), `font-black` (900)
- **Tracking:** Uppercase labels use `tracking-[0.2em]` or `tracking-[0.3em]` and `tracking-wider`
- **Leading:** Default, with occasional `leading-none` for logos, `leading-relaxed` for verses

### Common Patterns
- Page titles: `text-xl md:text-2xl font-bold tracking-tight`
- Section headings: `text-sm md:text-base font-bold tracking-tight` (with accent indicator bar)
- Song titles: `text-sm font-semibold tracking-tight`
- Song author: `text-[11px] font-medium text-neutral-400`
- Badges ("New", "Short"): `text-[8px] font-bold uppercase tracking-wider`
- Metadata: `text-[10px] font-medium uppercase tracking-wider`
- Verse text: `text-xs italic leading-relaxed`

## 4. Component Architecture

### Home Page (`/`)

Sections in order:
1. **Hero** — Gradient banner with verse cycling (8s interval), song count stats, currently playing indicator
2. **Spotlight** — Single featured track (random from top 5), large gradient card with play button
3. **Featured** — Horizontal scroll (15 songs, praise-first), Spotify-style cards with gradient background
4. **New Additions** — Horizontal scroll (songs within 30 days), featured-style cards
5. **Recently Played** — Horizontal scroll (persisted via localStorage & Supabase), rail cards
6. **Recommendation** — Vertical list (10 random songs, changes on reload), simple row cards
7. **End-of-page divider** — Thin line + "that's all for now" message + Refresh button

### Songs Page (`/songs`)
- Search bar + Filter button (time, category, duration chips)
- Alphabetically grouped songs (A–Z)
- Each row: avatar, title, author, "New" badge, more menu (info, add to playlist, download, save)
- Download manager integration (IndexedDB-based offline storage)
- Active song shows waveform equalizer icon

### Library Page (`/library`)
- Tabbed: Saved | Playlists | Downloads
- Saved songs: alphabetically grouped, click to play
- Playlists: grid cards, create/delete
- Downloads: device storage meter, downloaded song list with remove

### Player (Dual-mode)

**Desktop Bar** (fixed bottom, hidden on mobile):
- Gradient progress bar (interactive)
- Song info (avatar + title + author)
- Controls: shuffle, prev, play/pause, next, repeat
- Time display (current / remaining)
- Volume slider
- Like (heart) button

**Mobile Mini-bar** (fixed above BottomNav):
- Thin progress bar
- Avatar + title + author
- Play/pause button
- Tap to open full-screen player

**Mobile Full-Screen Player** (overlay, z-99999):
- Full-bleed gradient background from song title
- Header: chevron-down (back), "Now Playing", like button
- Large initial letter (artwork)
- Song title + author
- Glass-morphism controls panel (`backdrop-blur-2xl`, white/10 bg)
  - Seek bar (custom styled range)
  - Controls: shuffle, prev, play/pause (large white circle), next, repeat
  - Volume slider
- Back button closes player (mobile back button also closes via history popstate)

### SongAvatar Component
- Renders first alphabet letter of song title on a pastel gradient background
- Sizes: xs (24px), sm (28px), avatar-mini (32px), md (40–48px), lg (48–56px)
- `rounded-xl` or `rounded-md` depending on size
- White text, shadow-sm

## 5. UX Patterns

### Song Selection & Playback
- Click song → sets active song + queue → auto-plays
- Eager play attempt on audio URL change + `onCanPlay` backup
- Queue-based navigation (next/prev within current section's list)
- Shuffle and repeat modes
- Cross-page queue persistence (shared PlayerContext)
- Previously playing song continues across page navigations

### Recently Played
- Stored in localStorage (`earlymusic_recently_played`)
- Synced to Supabase `recently_played` table when authenticated
- Max 10 items, newest first
- Seeds with 6 random songs for new users
- Displayed in Sidebar (desktop) and Home page (mobile)

### Song Saving (Liking)
- `saved_songs` table in Supabase (user_id, song_id)
- Toggle from SongItem menu, Player like button
- Synced per-user, shown in Library > Saved tab

### Download for Offline
- IndexedDB via `downloadManager.js`
- Cache management with storage quota display
- Download/remove from song context menu
- Shown in Library > Downloads tab

### Authentication
- Supabase Auth (email/password)
- AuthContext provides user, profile, admin check
- Protected routes: Library (redirect to sign in)
- Admin role via `user_roles` table

### Caching
- Songs list cached in localStorage (`earlymusic_songs_cache`)
- Audio files cached via Cache API (`earlymusic-audio-cache-v1`)
- Offline indicator in header when `navigator.onLine` is false

### PWA
- Manifest: `/manifest.json`
- Service worker via next-pwa / SWRegister
- InstallPrompt component
- Apple web app capable with status bar styling

## 9. Data Flow

### Song Playback
```
User clicks song
  → setActiveSong(song, queue) in PlayerContext
    → activeSong = song, queue = customQueue
    → recentlyPlayed updated (localStorage + Supabase)
  → Player re-renders with new song
    → loadAudio() async
      → getAudioPublicUrl(song.song_path)
      → getCachedAudioUrl() (Cache API lookup)
      → setAudioUrl() → <audio> src changes
      → playRef = true
    → Eager play attempt on audioUrl change
    → onCanplay fires as backup
```

### Recently Played Sync
```
Play song → update localStorage → debounce → upsert to Supabase
On mount → load from localStorage → if empty, seed with 6 random songs
```
